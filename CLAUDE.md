# subgraphs-network-exporter — context

Zero-dependency Bun Prometheus exporter for The Graph **network subgraph** (on-chain indexer
economics). One file: `src/index.ts`. Pure render/format helpers are exported and unit-tested
(`bun test`); the poll loop + `Bun.serve` only run under `import.meta.main`.

## Why this exists

Extracted from the inline Python `stake-exporter` ConfigMap in `../k8s-subgraphs` (pinax2). Reasons:
consistency with `../subgraphs-qos-exporter` (Bun, no Python), the inline Python-in-YAML blob had
grown unwieldy (stake + names + allocations + signal), and we want to observe **multiple / any**
indexers, not just ours. Metric names are kept identical to the old exporter (plus an
`indexer`/`indexer_name` label on `indexer_subgraph_allocated_grt`) so Grafana keeps working.

## Ecosystem

- `../subgraphs-qos-exporter` — sibling Bun exporter (gateway QoS feed via on-chain DataEdge). This
  repo mirrors its structure (Dockerfile, `.github/workflows/docker.yml` → GHCR, tsconfig, tests).
- `../k8s-subgraphs` — Flux GitOps cluster (riv-dev1). Hosts the deployment manifests. The old
  `pinax2/stake-exporter.yaml` (inline ConfigMap) is what this replaces.
- `../subgraphs-grafana` — dashboards-as-code that CONSUME these metrics.

## Deploy flow

Push to `main` → CI (`docker.yml`) type-checks, `bun test`, builds & pushes
`ghcr.io/pinax-network/subgraphs-network-exporter:latest`. A `k8s-subgraphs` Deployment pulls that
image; Flux rolls it out.

## Indexer names & scopes

- Indexer display names come from committed **`indexers.json`** (`{wallet: name}`), baked into the
  image, regenerated by `scripts/gen-indexers.ts` (ENS reverse → `defaultDisplayName` → URL host).
  No `defaultDisplayName` on the runtime critical path — a schema hiccup can't take down stake metrics.
- `gen-indexers.ts` filters `stakedTokens_gt: MIN_STAKE_GRT` (default 100000) → prunes deregistered /
  sub-floor indexers. Seed was copied from `subgraphs-qos-exporter/indexers.json`.
- Two scopes: `INDEXERS` (detail: stake + allocations + signal + names) and `ALL_INDEXER_STAKE`
  (stake-only gauges for every registered indexer over `MIN_STAKE_GRT`, via one batched query — never
  fan out per-indexer allocation queries across hundreds of indexers).

## Dependencies

- Bun only: `package.json` sets `packageManager` and `devEngines`, so npm refuses to install or run
  scripts here. Use `bun install`, `bun run <script>` and `bun add <pkg>`.
- CI installs with `bun install --frozen-lockfile`; the Docker image has no install step (no runtime
  dependencies). Commit `bun.lock` with every dependency change.
- `bunfig.toml` lets `bun add` and `bun update` pick only versions published at least 5 days ago
  (`minimumReleaseAge = 432000`, in seconds) and saves exact versions. `.npmrc` sets
  `min-release-age=5` (in days) for any npm still in use.
- Never download a tool on the fly (`npx <pkg>`, `bunx <pkg>`, `<pkg>@latest`): add it as a pinned
  devDependency and run `bunx --no-install <bin>`.
- No Dependabot or Renovate: update dependencies by hand and review the `bun.lock` diff.

## Conventions

- Keep it dependency-free at runtime (Bun global `fetch`). Types-only devDeps (`@noble/hashes` is used
  only by the out-of-band gen script, never at runtime).
- A failed refresh keeps last-good metrics and only flips `_up`; fast-retry 30s.
- GRT = wei/1e18 via `BigInt` then `Number` (exact int, then divide).
- Commit trailers: `Co-Authored-By: Claude ...` and `Claude-Session:` per the session.
